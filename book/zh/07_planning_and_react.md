# 第7章 规划、ReAct 与失败后的重新决策

## 7.1 计划是可修改的假设

研究计划描述“根据当前信息，我们认为下一步应该怎样做”。它不是已经证明可行的事实。一个 Agent 生成了十步计划，并不意味着十步都能执行；其中可能缺少数据、软件、权限或独立样本。

因此，规划应当包含前提条件和停止条件。比如“在完成样本对应检查后计算跨组学关联”，前提是数据确实来自可配对的样本。如果发现两个组学来自不同人群，计划必须改变，而不是通过排序行号强行配对。

本书把计划分成目标、任务、依赖和验收四个部分。目标说明为什么做；任务说明做什么；依赖说明先后关系；验收说明什么情况下算完成。计划本身也应保存版本，并记录为什么修订。

## 7.2 ReAct：行动让推理接触现实

ReAct 的关键思想是交替进行推理与行动，让外部反馈参与后续决策，而不是只在模型内部连续生成解释。[R02] 在实际工程中，我们可以保留简短的行动理由、工具请求和观察结果，不需要依赖长篇内部思考记录。

例如：系统发现当前只知道代谢物名称，先调用实体映射；发现名称对应多个异构体，暂停机制查询；获得准确标识后，再查询反应或靶点信息。这里的改进来自新的观察改变了行动，而不是来自文字变得更长。

一个可审计步骤可以写成：

```json
{
  "decision": "resolve_entity",
  "reason": "Metabolite name is ambiguous",
  "tool": "chemical_lookup",
  "arguments": {"name": "candidate M"},
  "expected_result": "stable chemical identifier"
}
```

观察结果必须单独保存，不能把预期结果当成实际结果。如果工具返回“无法区分”，系统应该保留不确定性，并请求能够区分实体的材料。

## 7.3 Plan-and-Execute：先画路线，再逐段执行

另一种常见结构是先生成计划，再由执行器逐项完成。它适合整体目标较复杂、但部分步骤可以预先确定的任务。计划层可以调用模型，执行层则尽量使用稳定的工具和规则。

问题在于，初始计划可能建立在错误前提上。因此不能把计划冻结成一张不可更改的清单。应在关键节点重新检查：输入有没有变化，前置任务是否通过，原目标是否仍然可实现。

对 MicroMetaCell 案例，初始计划可能是数据审计、候选边识别、证据检索、竞争机制比较和报告。若数据审计发现没有受试者对应信息，候选边识别就不能按配对相关分析执行。合理的重规划是退回跨研究证据汇总，而不是编造配对关系。

## 7.4 什么时候应该重规划

不是所有错误都需要调用规划模型。文件名拼写错误、必填字段缺失和数值非有限，通常可以用确定性规则处理。只有当问题改变任务可行性或方法选择时，才值得重规划。

本书建议区分四种情形。**机械修复**处理明确的小错误；**有限重试**处理临时故障；**方案替换**处理工具不可用但目标仍可实现；**目标降级或停止**处理关键数据或证据不存在。把所有问题都交给“Reflection 再想一次”，会浪费调用并掩盖故障类型。

重规划记录应说明被推翻的前提，而不只是给出一份新计划。例如：“原计划要求同一受试者的微生物和代谢物配对数据；当前只有独立队列，因此不再估计样本级关联。”这条记录对最终报告非常重要。

## 7.5 行动选择与信息价值

在多个可行动作中，Agent 应优先选择能够减少关键不确定性的动作，而不是最容易生成漂亮输出的动作。假设有两个候选机制：M 直接作用于细胞 C，或 M 只是另一过程的伴随标志。继续查十篇相关综述，可能不如找到一项有明确时间顺序或扰动设计的研究更有区分力。

可以用一个概念性目标表示行动选择：

$$a^*=\arg\max_a\left[\operatorname{ExpectedInformationGain}(a)-\lambda\operatorname{Cost}(a)\right].$$

这不是本书声称已经实现的万能计算公式。真实系统往往无法准确估计信息增益，只能用可解释的启发式近似。例如优先补齐证据链中最薄弱的边，或优先解决实体歧义。重要的是明确近似，而不是给一个未经验证的数字冠以最优决策之名。

## 7.6 停止条件比无限反思更重要

一个系统可以因为成功、预算用尽、证据饱和或无法推进而停止。成功要求验收通过；预算停止要求报告未完成部分；证据饱和表示在预定检索策略下没有新的有效信息；无法推进则应指出缺少什么输入。

不要把“连续三次回答相似”当作证据充分。输出重复可能只是模型陷入固定模式。也不要因为假设评分持续升高就认为越来越接近真实机制；评分可能只是更符合当前评审提示词。

下面的伪代码展示一组比单一循环次数更明确的停止条件：

```python
if all_required_checks_passed:
    stop_reason = "completed"
elif calls_used >= call_budget:
    stop_reason = "budget_exhausted"
elif repeated_failed_action:
    stop_reason = "blocked"
elif no_new_evidence_after_planned_searches:
    stop_reason = "evidence_saturation"
else:
    stop_reason = None
```

## 7.7 练习与参考思路

**练习一：**模型计划先做通路富集，再核对基因标识。参考思路：标识映射是富集分析的前置条件，应先检查物种、命名空间和可映射比例。计划的自然语言顺序不能凌驾于分析依赖。

**练习二：**工具不可用，模型建议改用另一个方法。参考思路：不仅检查新方法能否运行，还要检查它回答的科学问题是否相同。不同输出不能因为名字相似就被视为等价替代。

**本章要点：**计划是带前提的可修订对象；重规划应由具体反馈触发；停止条件必须显式化。
