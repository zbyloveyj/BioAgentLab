# 实训五 亲手运行一场假设锦标赛

## 目标与比较标准

本实训不评价真实生物机制，而是理解成对结果如何形成排名，以及排名怎样受到评审和赛程影响。准备三个候选A、B、C，先用人工指定的结果替代模型评审，避免把语言能力与排序数学混在一起。

```python
from bioagent.ranking import elo_pair, tournament

print(elo_pair(1000, 1000, 1))
print(elo_pair(1000, 1000, 0.5))
```

第一行应返回1012与988，第二行保持相同分数。解释为什么双方总分不变，以及K值只决定更新速度而不具有生物学意义。

## 构造循环偏好

设A胜B，B胜C，C胜A。这种循环可能来自不同评价维度，也可能来自评审不一致。它提醒我们，候选不一定存在一个稳定的单一顺序。

```python
wins = {("A", "B"), ("B", "C"), ("C", "A")}
def judge(left, right):
    return 1.0 if (left, right) in wins else 0.0

result = tournament(["A", "B", "C"], judge)
print(result["ratings"])
print(result["matches"])
```

不要因为最终仍产生一个第一名，就认为循环问题被解决。排序器始终可以输出数值，但这些数值的解释依赖比较数据。

## 改变赛程顺序

使用同一judge，改变候选输入顺序，再比较结果。动态Elo更新可能产生不同分值。把结果按候选ID对齐后比较，不要只看打印顺序。

```python
orders = [["A", "B", "C"], ["C", "B", "A"], ["B", "A", "C"]]
for order in orders:
    ratings = tournament(order, judge)["ratings"]
    print(order, {key: round(ratings[key], 3) for key in sorted(ratings)})
```

这不是程序错误，而是在线更新的一项特性。若研究需要稳定优先级，可以重复赛程并报告敏感性，或使用适合成对数据的其他模型；无论怎样，都不能忽视评审标准本身。

## 区分平局与无法比较

把A与B的结果设为None，表示材料不足以比较。程序应记录 `not_comparable`，而不是把它当成0.5。真正平局则表示有足够材料，但在当前标准下接近。

```python
def incomplete_judge(left, right):
    if {left, right} == {"A", "B"}:
        return None
    return 0.5

result = tournament(["A", "B", "C"], incomplete_judge)
for match in result["matches"]:
    print(match)
```

在真实评审中，无法比较的原因也应保存，例如某候选缺少实验条件。否则读者无法区分证据空缺与评审者不确定。

## 设置资格门槛

为候选添加资格字段，例如是否有可检验预测、是否存在未解决的阻断性批评。先排除不合格候选，再进行优先级排序。否则即使所有候选都不合格，也会产生一个看似值得实施的冠军。

资格门槛不能等同于“已有最多证据”。某些新假设证据有限，但可检验且有价值。门槛应针对不可接受的缺陷，优先级则体现研究目标与资源权衡。

## 接入模型评审前的检查

模型评审需要相同格式材料、明确维度、展示顺序控制和引用检查。输出应包括结果、简短理由与证据标识。新增事实性论点必须进入检索核验，而不直接改变排名。

可以先让两位评审独立比较，再交换展示顺序。若同一候选只因为放在前面而获胜，说明需要处理位置偏差。多个模型角色不自动成为独立专家。

## 提交与参考答案

提交三种赛程的分值、循环偏好的解释、一个无法比较案例，以及资格门槛设计。参考答案应指出排名是相对偏好，不是机制真实性概率；赛程、评审和材料都会影响结果。

扩展任务是改变K并比较稳定性。不要把更大的分值差解释成更多科学证据，因为它可能仅由K变化造成。
