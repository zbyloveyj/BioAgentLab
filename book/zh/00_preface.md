# 前言：把会说话的模型变成可检查的科研系统

本书面向已经接触过生物学、生物信息学或医学研究，却尚未系统学习 AI Agent 的读者。它不要求你先训练一个大语言模型，也不把熟记框架名称当作学习目标。我们要解决的是一个更具体的问题：当研究任务同时需要阅读文献、检查数据、选择软件、比较解释和记录不确定性时，怎样把这些活动组织成一个可以运行、可以检查、可以被纠正的系统？

贯穿本书的例子是“微生物—代谢物—宿主单细胞”。假设研究者观察到某类微生物与疾病表型有关，希望进一步识别可能连接微生物功能、代谢变化和宿主细胞状态的机制。这里的困难并不只是代码难写。物种丰度不等于功能活性，粪便代谢物不等于循环暴露，细胞中出现受体转录本不等于受体被激活，多个关联连在一起也不自动成为因果链。一个可靠的科研 Agent 必须认识这些边界。

我们的基本分工是：语言模型理解目标、提出候选行动和解释已有结果；专业软件执行统计与生物信息学计算；数据库和原始研究提供可以定位的证据；规则和评估系统检查输入、输出与权限。没有哪一部分单独保证结论正确。工程上的可靠性来自这些部分之间明确的接口，以及出错时不掩盖错误的设计。

## 怎样阅读这本书

第一遍建议顺序阅读基础、工具、检索和科学推理部分，先建立完整地图。遇到代码时不必马上逐行背诵，但应理解输入是什么、输出是什么、失败会在哪里发生。第二遍运行配套项目，再回到相应章节查明设计理由。最后选择一个具有明确数据边界的小问题，替换教学数据，观察哪些假设不再成立。

每章都提供概念解释、工作示例、工程或科学陷阱，以及带参考思路的练习。正文中的短代码用于说明局部概念；完整实现位于仓库的 `bioagent/`、`examples/`、`tests/` 和 `notebooks/`。凡是涉及真实外部服务的示例，都与离线演示分开。运行离线教学案例不要求填写模型 API 密钥。

本书不是一份把聊天记录机械拼接起来的资料。前面的章节建立后面反复使用的数据结构和判断标准；后面的生物学案例则用来检验这些标准是否足够。读者最终应当能够解释：为什么某项分析应该由确定性的 workflow 完成，为什么另一项任务需要模型动态选择行动，以及为什么有时最正确的输出是“当前证据无法区分这些解释”。

## 本版的范围与证据约定

本版是 BioAgentLab 的中文教学版，不是临床诊断系统，也不是经过前瞻性验证的自主发现平台。配套的合成数据、演示假设和示例评分用于检验程序行为，不代表真实队列结果。文献案例按照明确列出的论文或版本介绍；引用预印本时标注预印本，不用系统名称的知名度替代同行评议状态。

全文使用四种不同的陈述。**事实**应当能够追溯至文献、数据库或具体文件；**计算结果**应当能够追溯至输入、代码和运行记录；**解释**是对事实与结果的推理，必须容纳替代解释；**假设**则是尚待验证的预测。你会发现，这四种陈述被混在一起，往往比某个模型调用失败更危险。

为了方便检索，参考资料统一用 `[R01]` 这样的编号。参考资料页列出原始论文或官方文档入口，访问核验日期为 2026 年 10 月 4 日。模型产品名称、接口和默认参数可能变化；本书优先讲解不依赖某一个供应商的接口思想，并在代码中将供应商适配与研究逻辑分开。

## 从书到项目

你可以把这本书看作一套逐层建立的研究工具。最底层是稳定的数据契约和日志；其上是检索、证据台账与工具注册；再上面是生成、反思、辩论、排名和修订；最上面才是特定领域的研究工作流。不要反过来，先画一个庞大的多智能体组织图，再希望底层细节自行成立。

最终项目的名称为 MicroMetaCell 教学工作流。它从一个研究问题出发，检查数据说明，建立待核验的边，检索局部证据，比较候选解释，并产生一份包含支持、冲突、空缺和下一步任务的报告。真实数据分析必须由读者在自己的合规环境中接入。软件能否运行与科学结论能否成立，将在本书中始终分别讨论。

学习的终点不是让 Agent 说得越来越像研究者，而是让研究过程留下越来越清楚的依据。
