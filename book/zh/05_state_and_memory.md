# 第5章 状态、记忆与可追溯的研究过程

## 5.1 当前状态究竟是什么

一个 Agent 运行到第五步时，程序应该知道已经完成什么、失败过什么、还有哪些证据缺口、哪些行动已获批准。这些信息共同构成状态。状态不是聊天记录的别名，而是下一步决策所必需的信息集合。

例如，一个研究任务已经完成实体映射和文献初筛，但某篇全文获取失败。状态应该分别记录三个任务的结果，而不是写“文献分析基本完成”。模糊状态容易使后续步骤误把未完成的工作视为已完成。

本书建议任务使用有限的状态集合：`pending`、`running`、`succeeded`、`failed`、`blocked` 和 `cancelled`。`blocked` 表示正在等待输入、权限或人工判断，不是执行失败；`succeeded` 则必须由实际验收规则确认。

## 5.2 状态转换应受规则约束

一个任务不能从尚未启动直接跳到成功，也不能在已经取消后继续写入结果。通过显式状态机，可以阻止模型随意宣称完成。下面的表描述一个简化版本。

| 当前状态 | 允许进入 | 含义 |
| --- | --- | --- |
| pending | running、blocked、cancelled | 准备执行或等待条件 |
| running | succeeded、failed、blocked | 根据真实执行结果更新 |
| blocked | pending、cancelled | 条件满足后重新排队 |
| failed | pending、cancelled | 有理由的重试或停止 |
| succeeded | 无 | 用新任务表示再次分析 |

把成功状态设为终态，可以避免悄悄覆盖原有结果。需要改变参数时，应创建新的运行版本，并建立与旧任务的关系。这样读者能够分清“原分析”“重试”和“新分析”。

```python
ALLOWED = {
    "pending": {"running", "blocked", "cancelled"},
    "running": {"succeeded", "failed", "blocked"},
    "blocked": {"pending", "cancelled"},
    "failed": {"pending", "cancelled"},
    "succeeded": set(),
    "cancelled": set(),
}


def transition(current: str, target: str) -> str:
    if target not in ALLOWED[current]:
        raise ValueError(f"Invalid transition: {current}->{target}")
    return target
```

## 5.3 三种记忆，三种用途

**工作记忆**保存当前任务直接需要的信息，例如候选假设和最新工具输出。**情节记忆**保存一次次运行发生的事情，例如某种输入触发了什么错误。**语义记忆**保存已经整理过的知识条目，例如数据库字段含义或经过核验的实体别名。

这三类记忆可以存储在同一数据库，但应有不同的字段和检索规则。失败记录不能被当作可靠生物学事实；某次研究中的相关关系也不能不加条件地进入永久知识库。Reflexion 展示了通过语言反馈与情节记忆改善后续行动的思路，但这不等同于模型参数训练，也不保证反馈内容正确。[R04]

对科研系统而言，最值得保存的记忆通常不是完整对话，而是结构化经验：“某数据版本的基因标识含版本后缀，映射前需要处理；该处理改变了多少条记录；由哪个测试验证。”这样的记忆比“下次要更仔细”更可复用。

## 5.4 记忆需要来源和有效期

每条可复用记忆至少应包含来源、创建时间、适用范围和版本。涉及外部数据库时，还应保留访问日期或数据库版本。把某个旧版本参数写成永远有效的规则，会使长期记忆逐渐成为错误来源。

一个实用的记忆条目可以包含：`memory_id`、`kind`、`content`、`source_ids`、`scope`、`valid_from`、`superseded_by`。检索时不仅比较文本相似度，还要过滤任务范围和有效状态。

设某项目采用人类基因标识，另一个项目采用小鼠同源基因。两个任务都出现“受体表达”这个短语，并不意味着可以直接共享映射结果。物种、组织、测量技术和标识版本都是记忆的适用条件。

## 5.5 事件日志与当前快照

当前快照便于快速决策，事件日志便于追溯历史。两者可以同时保留：每发生一个动作，写入不可随意覆盖的事件；再根据事件更新当前任务状态。出现异常时，可以检查系统在什么地方偏离了预期。

事件中应包括时间、运行标识、任务标识、动作名称、输入摘要、输出摘要和错误类别。敏感正文或巨大矩阵不宜直接写入日志，可以保存受控文件的引用与哈希。日志也需要访问控制，不能因为它是调试信息就忽视隐私。

```python
import json
from datetime import datetime, timezone
from pathlib import Path


def append_event(path: Path, event: dict):
    row = {
        "time": datetime.now(timezone.utc).isoformat(),
        **event,
    }
    with path.open("a", encoding="utf-8") as handle:
        handle.write(json.dumps(row, ensure_ascii=False) + "\n")
```

这个 JSONL 方案适合单进程教学。多进程写入和生产系统需要更可靠的事务、锁或日志服务。不要把“能写文件”误认为“已经具备并发一致性”。

## 5.6 失败恢复与幂等性

网络请求可能成功，但程序在保存结果前崩溃。恢复时再次执行，会不会重复写入、重复扣费或重复发送？这就是幂等性问题：同一个操作执行多次，是否产生与执行一次相同的效果。

读取数据库通常比写入操作容易安全重试，但即使读取也可能触发计费。对于写入，应使用任务键、去重标识或事务记录。恢复逻辑首先检查动作是否已经产生有效输出，而不是盲目从头执行。

科研计算也需要类似机制。一个长流程完成了比对，下一步统计失败，不应无理由重新比对全部样本。可恢复工作流应根据输入、参数、工具版本和输出哈希判断中间产物是否可复用。

## 5.7 摘要不能替代原始证据

为了节约上下文，系统会摘要旧记录。但摘要可能丢失否定词、研究对象和限制。例如“未发现显著升高”被压缩成“与升高有关”，会改变科学含义。任何由摘要支持的重要结论，都应能回到原始片段。

可以把摘要看成目录卡片，而不是证据本身。目录卡片帮助决定去哪里查找，真正核验仍使用原始记录。尤其在多轮假设修订中，不能只保留越来越短的摘要，否则不确定性容易被逐步删除。

## 5.8 练习与参考思路

**练习一：**一次任务声称成功，但输出文件不存在。参考思路：任务状态与验收结果矛盾，应记录失败或异常，而不是根据模型声明保留成功状态。

**练习二：**一条长期记忆说“某工具参数默认是 X”，如何判断还能否使用？参考思路：检查工具版本、记忆来源与更新时间；在实际运行环境查询帮助或官方文档，并让测试覆盖相关行为。

**本章要点：**状态用于控制，记忆用于复用，事件用于追溯；三者都必须保留适用范围与版本。
