# 第9章 检索与 RAG：先找到材料，再组织回答

## 9.1 RAG 解决的是信息接入问题

检索增强生成把外部资料引入模型回答过程。它让系统不必仅依赖参数记忆，可以使用指定文献库、内部文档或当前数据库记录。经典 RAG 工作将检索器与生成模型结合，构成参数知识与非参数知识的混合系统。[R03]

但 RAG 不自动保证答案正确。检索器可能漏掉关键证据，切分可能破坏上下文，生成器可能误解材料。一个带引用的答案，甚至可能只是“引用存在，但不支持这句话”。因此，检索、证据核验和写作应分开评估。

在本书中，RAG 的第一目标是可追溯的信息接入，而不是让答案变长。每个被检索片段必须具有文档标识、位置、来源与版本，使读者能返回原文。

## 9.2 建库之前先定义文档单位

文档可以是一篇论文、一个数据库记录、一段方法或一次工具输出。不同单位有不同用途。论文摘要适合初筛，不一定足以核对实验细节；全文方法适合检查设计；数据库记录适合实体映射，但可能缺少完整的研究背景。

不能把不同单位直接当成独立证据相加。一篇论文的摘要、全文和新闻稿可能都描述同一研究。若不去重，检索系统会把传播广泛误认为证据丰富。建库时应保留 `study_id` 与 `document_id` 的区别。

还要记录资料的使用权限。能够在网页上阅读，不等于可以重新分发全文。教材仓库应保存自己编写的说明、合法的元数据和必要的短摘录，不应把受版权限制的论文整批上传。

## 9.3 切分：不要把否定词切掉

最简单的切分方法按固定长度分块，但科学文本往往依赖段落、表格和上下文。一个句子说“在控制协变量后该关联不再显著”，若只保留前半句，就会改变含义。图注、方法说明和补充材料也不能只按字符数随意截断。

实用策略是先按章节和段落切分，再在过长段落内部细分，并保留有限重叠。每个片段应携带上级标题与原始位置。对于表格，应保留列名、单位和脚注，否则一组数字很难正确解释。

重叠有助于保留上下文，但会增加重复命中。检索后应合并相邻片段，并在证据计数时回到研究单位，而不是按 chunk 数量计数。

## 9.4 稀疏检索与稠密检索

稀疏检索关注词项匹配，适合稳定标识、基因符号和精确术语。稠密检索把文本映射到向量空间，适合语义相近但措辞不同的查询。两者并不互相替代：对一个精确的化学标识，词项检索可能比语义近邻更可靠。

向量相似度常用余弦形式：

$$\operatorname{cos}(q,d)=\frac{q^\top d}{\|q\|\|d\|}.$$

相似度高表示表示空间中的接近，不等于证据支持强。两篇相似的文章可能一篇支持、一篇反对同一结论。因此，检索评分只用于选择待阅读材料，不能直接成为科学证据分数。

本书的离线项目实现轻量词项检索，便于不依赖外部模型运行。它不声称等价于先进嵌入模型，也不把教学检索器的性能推广到真实医学文献库。

## 9.5 一个可读的词项检索基线

下面的例子用集合重叠演示检索接口。它不是正式 BM25，也不适合直接用于大规模检索评估，但足以说明文档标识与结果排序如何连接。

```python
import re


def tokens(text):
    return set(re.findall(r"[a-z0-9_]+|[\u4e00-\u9fff]", text.lower()))


def search(query, documents, top_k=3):
    q = tokens(query)
    scored = []
    for doc in documents:
        d = tokens(doc["text"])
        score = len(q & d) / max(1, len(q | d))
        if score > 0:
            scored.append((score, doc["id"], doc["text"]))
    return sorted(scored, reverse=True)[:top_k]
```

这个分词方法对中文只是教学处理，不能充分识别生物医学术语。真实系统应评估领域分词、实体标准化和跨语言检索，并通过已标注问题检查召回情况。

## 9.6 重排序与检索多样性

初次检索可以返回较多候选，再用重排序器或规则选出最相关材料。重排序时应考虑与问题的直接关系、研究对象、时间、证据类型和来源独立性，而不只是语义相似。

如果前十条结果都来自同一篇论文的不同段落，模型看起来获得很多材料，实际覆盖面很窄。可以按研究分组，先选择不同研究，再在每项研究内选择最有用的片段。对于竞争机制，最好主动保留支持与冲突材料，而不是只保留与初始假设一致的内容。

“多样性”也不能盲目追求。与问题无关的材料不应仅为了增加来源数量而进入上下文。目标是在相关性与覆盖之间取得可解释的平衡。

## 9.7 检索系统怎么评估

给定一组问题和人工确认的相关材料，可以评估 Recall@k、Precision@k 等指标。Recall@k 关心前 k 条结果覆盖多少相关材料；Precision@k 关心返回结果中有多少相关。科研问题还应增加来源独立性和证据类型覆盖的检查。

一个检索器找到了主题相近的综述，却漏掉关键原始研究，普通语义相关性评分可能仍很高。因此评估集应包含需要核对原始实验、否定结果、物种差异和实体歧义的问题。

检索评估与回答评估必须分开。检索器找对材料但生成器解释错误，是不同于检索器根本没找到材料的故障。只有分开记录，才能知道应该改进哪一层。

## 9.8 练习与参考思路

**练习一：**同一研究的预印本与正式发表版本同时进入库，如何处理？参考思路：建立版本关系，避免当成两项独立研究；优先使用适当版本，同时保留差异与时间信息。

**练习二：**某个向量结果分数很高，却来自不相关物种。参考思路：增加实体和物种过滤，把语义相关性与适用范围分开；不能用相似度覆盖科学条件。

**本章要点：**RAG 提供外部材料，不代替核验；检索单位、研究单位和证据单位必须区分。
