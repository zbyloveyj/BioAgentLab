# 第2章 语言模型、上下文与不确定性

## 2.1 先理解模型在计算什么

语言模型通常把文本切分成 token，再根据已有上下文生成后续 token。token 不等于汉字、单词或字节；具体分词方式由模型决定。一个中文术语可能对应多个 token，一个英文缩写也可能被拆开。不要用固定“一个字等于一个 token”的估计制定精确预算。

对自回归语言模型，序列概率可以写作：

$$P(x_1,\ldots,x_T)=\prod_{t=1}^{T}P(x_t\mid x_1,\ldots,x_{t-1}).$$

这个公式表示每一步都依赖前面的内容，并不意味着模型只能做肤浅的词语接龙。复杂训练可以形成有用的表示与行为能力；但生成概率高，仍然不等于某项科学陈述为真的概率。Transformer 的注意力机制是理解现代语言模型的一条基础线索。[R01]

## 2.2 注意力可以怎样类比

阅读一篇论文时，你会根据当前问题回看不同位置。正在判断样本量，就会寻找方法和表格；正在解释机制，就会查看结果和讨论。注意力机制可以粗略理解为：计算当前处理位置与其他信息位置的相关权重，再综合这些信息。

常见的缩放点积注意力写为：

$$\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V.$$

不需要立即记住所有矩阵运算。关键是理解：模型不是只看最后一个词，而是在一定上下文范围内组合信息。另一方面，能访问上下文并不意味着一定正确使用每条信息。重要约束可能被忽略，不相关内容也可能干扰决策。因此，Agent 需要主动组织上下文，而不是不断堆积文本。

## 2.3 参数知识与外部证据

模型参数中可能保留某些知识，但参数记忆通常不能直接给出可靠的来源定位。模型生成一个 DOI，并不能证明该 DOI 存在；能够解释某个基因，也不代表它知道最新的命名、别名或数据库版本。

外部证据则是系统在当前任务中获取的可定位材料，例如一条数据库记录、一段论文方法、一份本地分析输出。外部材料同样可能错误或过时，但至少允许核对它来自哪里、何时获取、适用于什么条件。RAG 的基本思想就是把外部检索与生成结合起来。[R03]

在科研系统中，参数知识适合帮助提出检索词、识别可能的方法和构建初步假设；关键结论应尽可能依赖具体证据。最危险的情形不是模型完全不知道，而是它知道一部分，于是用熟悉的语言补齐了实际上缺失的部分。

## 2.4 上下文窗口不等于长期记忆

上下文窗口是一次模型调用可使用的信息范围。长期记忆则由应用程序保存，必要时再检索进入当前上下文。窗口很长不能替代记忆管理：把全部历史重新送入模型，可能增加成本，也可能引入过期判断和彼此冲突的版本。

设一个假设最初写作“代谢物 M 直接影响细胞 C”，后来证据核验发现只支持“受体相关基因在 C 中表达”。如果历史文本全部平铺进入下一次调用，模型可能重新使用最初的强因果表述。正确做法是把当前有效结论和历史修订分开，并明确标记哪个版本已被替代。

可以将一次科研调用的上下文分为四块：任务规则、当前状态、相关证据、待完成动作。每一块都应该有清晰边界。证据文本属于被分析的材料，不属于能够修改系统规则的指令。

## 2.5 温度与重复运行

温度等生成参数会影响输出分布，但“低温度”不是“事实更真”的同义词。某个错误答案如果已经具有较高生成概率，降低随机性反而可能让系统更稳定地重复错误。是否更适合某项任务，应通过任务评估而非直觉判断。

为了观察模型行为，你可以固定任务、资料、提示词和参数，重复运行若干次，比较结论差异。这里研究的是系统稳定性，而不是通过重复提问获得独立科学证据。十次调用同一个模型支持同一假设，不能当成十项独立研究。

```python
from collections import Counter

answers = [
    "insufficient", "supported", "insufficient",
    "insufficient", "supported",
]
counts = Counter(answers)
for label, n in sorted(counts.items()):
    print(label, n / len(answers))
```

这段代码只能描述输出频率。它没有证明“insufficient”的概率是真实世界中的 60%，也没有证明多数答案正确。把模型采样频率解释成已校准的科学置信度，需要额外验证。

## 2.6 三类不确定性

**资料不足**指当前没有取得必要信息，例如研究没有报告剂量。**测量与统计不确定性**来自数据噪声、样本量和估计误差。**模型与解释不确定性**则来自方法选择、假设空间或外推。它们的解决方式不同，不能全部压缩成一个信心分数。

对资料不足，可能需要补充检索；对统计不确定性，可能需要更大的独立样本或更适当的估计；对机制解释不确定性，可能需要能够区分竞争假设的干预。让模型“再认真想一次”并不能解决全部三类问题。

本书建议把不确定性写成结构化记录：`missing_information`、`measurement_limitations`、`alternative_explanations` 和 `next_discriminating_test`。自然语言中的“可能”很容易被后续摘要删掉，而显式字段更容易被程序检查。

## 2.7 不暴露内部思考也能可审计

研究系统需要记录决策依据，但不需要保存模型不可验证的内部思考过程。更有价值的是简洁的决策摘要：选择了什么行动、依据哪几条证据、还有什么空缺、为什么需要人工批准。工具参数和执行结果则应完整保存。

例如：“选择查询受体数据库，因为当前证据只覆盖微生物与代谢物之间的关联，缺少代谢物到宿主靶点的映射。”这是一条可检查的行动理由。它比一大段自由推理更容易与证据台账对应，也更容易发现错误。

## 2.8 练习与参考思路

**练习一：**模型给出“置信度 0.94”，你应如何使用？

参考思路：先问这个数是模型自报、经验规则还是经过校准的预测概率。没有校准证据时，应把它作为内部排序信号，而不是研究结论的可信概率。报告更应强调证据类型、独立来源和未解决的问题。

**练习二：**一个很长的上下文同时包含被否定的旧假设与新结果，如何避免旧假设复活？

参考思路：保存版本和有效状态，检索时优先提供当前版本；历史材料明确标记为已替代。最终报告中的每条强结论都必须重新检查证据，不依赖模型对聊天历史的模糊记忆。

**本章要点：**生成概率不是事实概率；上下文不是可靠记忆；不确定性应被分类，而不是被流畅的文字掩盖。
