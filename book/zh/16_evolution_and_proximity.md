# 第16章 Evolution 与 Proximity：修订而不丢失依据

## 16.1 好的修订改变可检验内容

假设进化不是把句子改得更专业，而是针对已确认问题调整机制、范围或预测。例如反思发现缺少体内暴露证据，合理修订可以缩小为“局部代谢关联”，或明确新增暴露测量作为必要前提。若只是加几个“可能”，原有逻辑错误仍然存在。

修订时应说明父版本、变化位置、变化原因和受影响的证据。这样读者能够看清假设如何从一个宽泛故事变成一个有边界的研究问题。没有版本记录的反复改写，很容易造成事后合理化。

本书使用“新对象”而不是原地覆盖。旧版本保留，新的版本拥有新的 claim 关联和核验状态。

## 16.2 证据不能无条件继承

假设从“代谢物 M 影响细胞 C1”改成“代谢物 M 影响细胞 C2”，旧文献仍然可以保存在资料库，但不能自动支持新陈述。来源可继承，支持关系需要重新建立。

同样，机制从“相关”改成“介导”后，原有横断面关联不能被当作新因果主张的充分依据。修订改变了 claim 的强度，也改变了证据要求。进化模块应使相应核验状态失效，再交给证据模块处理。

```python
from copy import deepcopy


def revise(parent, new_statement, new_claim_ids, reason):
    child = deepcopy(parent)
    child["version"] = parent["version"] + 1
    child["parent"] = f"{parent['id']}:v{parent['version']}"
    child["statement"] = new_statement
    child["claim_ids"] = list(new_claim_ids)
    child["revision_reason"] = reason
    child["verified_links"] = []
    child["status"] = "requires_reverification"
    return child
```

深拷贝只解决 Python 对象共享问题，不解决科学继承问题。真正的关键是显式清空或重新核验旧的支持关联。

## 16.3 变异与重组的边界

可以从一个候选中保留暴露机制，从另一个候选中保留宿主响应，但组合后不一定合理。两个片段可能来自不同组织、时间尺度或物种。重组生成的新假设必须重新审查连接条件。

一个实用规则是：每增加一条机制连接，就增加一项明确的桥接假设。比如从粪便代谢变化连接到中枢表型，可能需要暴露、转运或外周信号等桥接。不能因为两个端点分别有文献，就省略中间的生物学过程。

进化应受研究资源约束。一个修订后需要新增多个队列、多个组织和大量干预条件的假设，可能更加完整，却不适合当前项目。可行性与解释完整性需要同时考虑。

## 16.4 Proximity 比较的是什么

Proximity 模块用于识别重复或高度相似候选，减少资源浪费。最简单方法比较词项重叠；更复杂方法使用嵌入或结构化机制图。不同方法识别的是不同相似性。

两个句子用词相同，因果方向可能相反；两个句子措辞差异很大，机制却相同。因此，文本近似只能作为候选筛查，重要去重应比较主体、关系、客体、情境和预测。不能仅凭向量接近就删除一个可能有关键差异的假设。

中文系统尤其不能使用只识别英文字母的分词后，把所有空词集判为完全相同。空表示应被视为无法判断，或者使用适合中文的词项策略。

## 16.5 一个双语教学基线

下面的方法提取英文词项和中文相邻双字片段。它支持基本演示，但不理解专业术语，也不能判断机制等价。空文本与无有效词项需要明确处理。

```python
import re


def bilingual_terms(text):
    english = re.findall(r"[a-z0-9_]+", text.lower())
    chinese_runs = re.findall(r"[\u4e00-\u9fff]+", text)
    terms = set(english)
    for run in chinese_runs:
        if len(run) == 1:
            terms.add(run)
        else:
            terms.update(run[i:i+2] for i in range(len(run)-1))
    return terms


def similarity(left, right):
    a, b = bilingual_terms(left), bilingual_terms(right)
    if not a or not b:
        return 0.0
    return len(a & b) / len(a | b)
```

对于同一条空陈述，这个函数返回0而不是1，因为它不应成为合法候选。更上层的输入校验应提前拒绝空假设。

## 16.6 保留有意义的多样性

如果每轮只保留最高分候选，再从它生成所有后代，系统可能很快收敛到一种叙事。可以按机制类别保留代表，或者对具有不同可区分预测的候选设置保留配额。

保留多样性不是平均照顾所有观点。明显违反证据或无法检验的候选仍应淘汰。目标是防止早期评分偏差过早排除合理的替代解释。

在研究报告中，至少应保留最强竞争解释及其所需证据。最终只展示优胜故事，会掩盖系统探索过哪些可能性，也无法解释为什么某个后续实验具有区分力。

## 16.7 防止评分投机

如果进化模块知道评审喜欢某些词语，它可能通过添加“纵向”“多组学”“可验证”等表述提高分数，而没有真正改变设计。这类似对评分器的过拟合。

可以通过隐藏部分评估任务、使用独立复核、检查具体数据需求，以及比较修订前后的可执行差异来缓解。一个候选写了“考虑混杂”，不等于已经定义混杂变量；写了“外部验证”，不等于拥有独立数据。

每轮修订应回答：“新增了哪一项可执行检查？删去了哪一条不被支持的主张？”这两个问题比“文字是否更完善”更接近科学改进。

## 16.8 练习与参考思路

**练习一：**假设只改变了措辞，claim完全相同，是否必须撤销全部证据？参考思路：可以保留原支持关系，但应确认语义强度没有变化；若只是格式修订，应记录为非实质变化。

**练习二：**两个候选分别认为A导致M、M导致A，词项相似度很高，是否去重？参考思路：不能。方向是机制结构的一部分，应保留为竞争解释。

**本章要点：**进化需要版本与重新核验；去重应关注机制差异，而不仅是文字相似。
