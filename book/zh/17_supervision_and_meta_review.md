# 第17章 Meta-review 与 Supervisor：管理整个研究过程

## 17.1 局部聪明不等于整体可靠

生成模块可能提出有趣假设，检索模块可能找到相关论文，反思模块也可能发现问题，但它们组合后仍会失败。例如检索不断重复，反思反复要求更多证据，生成则不断改写目标，整个系统没有明确停止点。

Supervisor 的工作是协调任务，而不是成为一个什么都做的超级提示词。它维护目标、状态、预算与依赖，决定下一步交给哪个模块，并在条件不满足时停止。确定性规则应处理明确的控制问题，语言模型只处理需要语义判断的选择。

AI co-scientist 的多角色组织为这种协调思路提供了研究案例。[R05] 本书实现的是更小的教学运行时，重点在可检查接口，不宣称复现原系统的研究性能。

## 17.2 Meta-review 寻找跨候选的共同问题

单个 Reflection 面向一个假设；Meta-review 面向整个候选集合与历史反馈。它需要回答：“多个候选是否共享一个未证实前提？哪类错误反复发生？下一轮生成应该改变什么？”

例如所有候选都默认粪便代谢物能够进入目标组织，那么这个暴露假设应升级为全局证据缺口。继续优化某一个候选的措辞不会解决它。Meta-review 可以建议把资源转向暴露测量或相关资料，而不是再增加假设数量。

简单统计相同批评文本只能识别字面重复。真实主题合并应保留原批评标识，避免模型把不同问题错误合并。任何归纳都应该能够回到具体实例。

## 17.3 用任务路由代替无限对话

一个可执行路由表可以规定：实体不确定交给映射工具；证据缺失交给检索；来源不适用交给核验；分析单位错误暂停计算；候选重复交给去重；全部验收通过才交给报告。

```python

def route(state):
    if state["budget_left"] <= 0:
        return "stop_budget"
    if state["invalid_input"]:
        return "stop_input"
    if state["unresolved_entities"]:
        return "resolve_entities"
    if state["blocking_critiques"]:
        return "review_blockers"
    if state["missing_claims"]:
        return "retrieve_evidence"
    if not state["comparison_done"]:
        return "compare_hypotheses"
    return "write_report"
```

规则顺序体现优先级，应该接受测试。比如预算已经耗尽时，不能继续检索；输入无效时，不能直接生成完整报告。真实应用可能允许先保存部分结果，再停止，但必须说明停止原因。

## 17.4 资源分配要有可解释依据

Supervisor 可以根据任务重要性、证据缺口、预期信息价值和成本安排资源。一个实践策略是先解决可能推翻整个方案的前提，再处理局部修饰。这样可以避免在错误前提上完成大量精细计算。

例如样本是否真正配对，是跨组学相关分析的关键前提；在确认之前，没有必要花大量资源优化关联模型。又如目标代谢物标识有歧义，应该先解决实体问题，再查受体或通路。

资源分配规则本身也可能偏差。若只给当前高分候选更多检索机会，它们可能因得到更多材料继续占优。可以为每个候选提供最低检查预算，再根据明确缺口追加资源，并记录这种不均衡。

## 17.5 把失败分为可以修复与需要停止

工具超时可能可重试，数据缺失可能需要用户补充，伦理或权限问题必须停止相关行动，科学证据不足则应转化为有边界的报告。Supervisor 不应把这些情况统一处理成“再问模型”。

每次失败记录应有类别、影响范围、是否可重试和下一步建议。如果某个工具连续失败，应该触发熔断，避免循环。熔断不是证明工具永远不可用，而是在当前任务中停止无效消耗。

对于真实生物数据，人工升级条件尤其重要：新增敏感数据外发、改变预先指定分析、执行高成本计算或涉及实验实施的决策，都应有明确审批点。

## 17.6 报告前的最终闸门

在生成报告前，系统应检查每条结论是否绑定有效 claim，引用是否存在，计算结果是否来自成功任务，所有模拟内容是否保留标记，未完成任务是否被明确列出。

报告模型不应拥有修改分析结果的权限。它可以解释字段、组织段落和提炼限制，但不能为了叙事顺畅改变数字、删除冲突或新增来源。对数值和标识，可以采用模板插入而非自由生成。

一个很实用的检查是比较报告中的证据标识集合与台账中的集合。未知标识必须拒绝。更高级的检查还应验证每个引用与对应句子的关系，不能只检查编号存在。

## 17.7 人在回路中不是一句口号

人工复核必须说明复核什么、何时发生、能修改什么，以及修改后如何重新验证。如果只是最后给研究者一份很长的报告，声称“请自行检查”，并没有真正设计人机协作。

可以把审核分成数据入口审核、方法选择审核、关键 claim 审核和发布审核。每个审核项提供相关证据与差异，而不是要求审核者重读全部聊天历史。人的时间也是资源，应把信息整理到足以做决定的程度。

## 17.8 练习与参考思路

**练习一：**所有候选都被批评“缺少暴露证据”，下一轮应生成更多候选吗？参考思路：先把共同缺口升级为全局任务，判断是否能补证据；更多候选可能只是重复同一前提。

**练习二：**报告已经写完，但一个前置任务后来验收失败，应怎么办？参考思路：使相关报告结论失效，重新生成受影响部分，保留版本与原因；不能因为文档已经漂亮就忽视上游变化。

**本章要点：**Supervisor 管控制与资源，Meta-review 找共同失败模式，人工审核必须有明确对象和时点。
