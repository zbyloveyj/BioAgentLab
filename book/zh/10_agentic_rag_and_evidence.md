# 第10章 Agentic RAG 与证据台账

## 10.1 从一次检索到有目标的查证

普通 RAG 通常根据问题检索一批材料，再生成回答。Agentic RAG 增加了决策循环：系统先判断需要什么证据，检索后检查是否足够，再决定补充、改写查询或停止。这里的价值不在于多检索几次，而在于每次检索都针对一个明确空缺。

假设要核验“微生物 A 通过代谢物 M 改变细胞 C”。初次检索只找到 A 与 M 的人群相关研究，系统应识别缺少 M 到 C 的证据，而不是继续搜索更多 A 与 M 的类似文章。证据台账帮助把这种空缺显式化。

这个章节的设计是本书提出的教学工程方案，不应误认为某篇论文已经验证了所有细节。GeneAgent 的工作展示了把生成内容拆成可核对陈述、再利用领域数据库进行自校验的思路，为我们提供了有价值的参考。[R07]

## 10.2 先拆 claim，再谈支持程度

一条复合陈述可能包含多条关系：A 具有产生 M 的能力；A 的变化与体内 M 暴露有关；M 能够作用于细胞 C；C 的变化与目标表型有关。每条关系需要不同证据。只找到其中一条，不能把整条链标记为支持。

claim 应尽量具体，包括主体、关系、客体、方向、情境与范围。例如：“在某种测量与人群条件下，A 的相对丰度与 M 的粪便浓度正相关。”它比“A 调节 M”更容易核验，也更不容易跨越证据边界。

复合假设可以保留为研究目标，但核验应在原子 claim 层面进行。最终报告再把这些局部结果组合起来，并明确哪些边仍然缺失。

## 10.3 证据记录的最小字段

一个证据条目至少需要证据标识、研究标识、来源定位、适用 claim、方向、研究类型和限制。方向可以是支持、冲突或无法判断。研究类型应明确区分数据库注释、观察研究、干预研究和教学模拟。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Evidence:
    evidence_id: str
    study_id: str
    claim_id: str
    source: str
    direction: str
    design: str
    context: str
    limitation: str
    synthetic: bool = False
```

不要把 `confidence=0.9` 作为唯一证据字段。一个看起来精确的数字可能掩盖样本重叠、物种不匹配、测量层级不同或原文实际上没有支持结论。结构化限制比未经校准的精确分数更有价值。

## 10.4 证据独立性与重复传播

设有五条证据记录，其中三条来自同一队列、两条来自同一篇研究的数据库转载。五条记录不等于五项独立研究。证据台账应按来源关系合并，并保留队列重叠信息。

对教学排序，可以按 `study_id` 对同方向证据去重；真实项目还需要更细致地处理部分样本重叠与重复分析。同一队列使用不同方法可能提供方法敏感性信息，但不能当成完全独立的复现。

```python

def independent_support_count(items, claim_id):
    studies = {
        e.study_id for e in items
        if e.claim_id == claim_id
        and e.direction == "supports"
        and not e.synthetic
    }
    return len(studies)
```

这个计数不是证据质量评分，只是防止明显重复计数的一项检查。真实判断还需要阅读研究设计。

## 10.5 支持、冲突与缺失应并列保存

不要只为支持性证据设计字段。冲突结果可能来自不同人群、剂量、组织或时间，也可能真正挑战假设。系统应先记录冲突，再尝试解释；不能为了保持叙事连贯而删除。

没有找到证据应保留为缺失，不应自动变成反对。相反，一项研究报告无显著效应，也不等于证明效应为零；需要考虑估计值、置信区间和统计功效。证据台账的任务是保存这些区别，而不是过早给出单一结论。

建议 verdict 使用 `supported_in_context`、`conflicted`、`insufficient` 等明确语义，而不是简单的真或假。一个关系可能在某种条件下被支持，在另一种条件下仍不确定。

## 10.6 核验引用的三道门

第一道门检查来源存在：标识是否有效、文件是否可定位。第二道门检查内容匹配：材料是否真的讨论当前关系。第三道门检查适用范围：研究对象、组织、测量与设计是否允许当前表述。

例如某论文证明一种代谢物在培养细胞中影响信号通路，来源存在、内容相关，但不能直接支持“该代谢物在人群中介导疾病”。这种材料可以作为机制线索，必须明确外推限制。

一个成熟的证据核验器也应保留原文短片段与位置，便于人工复核。只保存模型的摘要，会让下一轮核验只能检查另一段模型输出，形成循环引用。

## 10.7 让缺口决定下一次查询

可以将每条必需边设为待核验任务。若某条边只有物种层面推断，下一次检索可针对菌株或功能证据；若缺少暴露信息，则查对应生物样本和测量方法；若缺少宿主响应，则查受体、转运体或扰动结果。

查询扩展应保存原始词与扩展词，避免系统在多轮检索后悄悄改变了研究问题。实体映射不确定时，应该先解决歧义，而不是同时把所有近似实体的结果混在一起。

当所有预定检索路径已经尝试而关键空缺仍存在时，合理输出是带空缺的证据报告。这不是任务失败，而是研究状态的准确表达。

## 10.8 练习与参考思路

**练习一：**一篇综述、一个数据库页面和一篇新闻报道都引用同一实验，如何计数？参考思路：它们是多个文档，但主要实验依据来自一项研究。应追溯原始来源，不把传播次数当作独立支持。

**练习二：**假设修改了客体细胞类型，旧证据能否直接继承？参考思路：来源文件可以保留，但与新 claim 的关联必须重新核验；旧 verdict 不能不加检查地沿用。

**本章要点：**Agentic RAG 应由证据缺口驱动；证据台账保存来源、范围和冲突，而不只是一个分数。
