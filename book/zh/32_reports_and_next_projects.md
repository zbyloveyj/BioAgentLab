# 第32章 研究报告、发布与下一项独立项目

## 32.1 最终报告不是一篇自由作文

研究报告应该忠实反映已经执行的过程。最少包含问题、数据范围、方法、结果、证据、限制和下一步。计划中的步骤、实际完成的步骤和失败的步骤必须分开。

对Agent生成的报告，可以先由程序生成结构化结果，再让模型辅助组织语言。数字、样本量、证据标识和状态尽量由模板插入，避免自由生成时发生漂移。

一个报告写得流畅，却找不到对应输入或运行记录，不应作为可信交付。可读性与可追溯性应该共同满足。

## 32.2 使用四层陈述

第一层是输入事实，例如样本数与数据类型；第二层是计算结果，例如明确工具产生的统计量；第三层是解释，例如某种共变结构可能意味着什么；第四层是下一步假设。四层应有不同的证据要求。

可以给报告字段增加类型标签，帮助后续检查。例如 `observation`、`computed_result`、`interpretation`、`hypothesis`。模型不能把第四层改写成第一层，也不能因为加入引用就把解释提升为事实。

```json
{
  "claim_type": "hypothesis",
  "text": "M may connect microbial function and host state",
  "source_ids": [],
  "limitations": ["No real biological validation in this demo"],
  "next_step": "Acquire context-matched evidence"
}
```

## 32.3 限制应该具体到结论

“本研究仍有局限”太笼统。限制应说明影响哪条结论、为什么影响，以及什么证据可以改善。例如缺少循环暴露，限制的是从局部代谢变化到远端细胞作用的推断；缺少独立供体，限制的是群体层面统计泛化。

把限制只放在报告末尾，正文仍使用确定性因果语言，会造成读者误解。关键限制应与相关结论并列出现，最终摘要也不能删除。

报告也应区分无法完成与不适合完成。前者可能是网络故障，后者可能是数据设计不允许。解决方式不同，因此需要不同说明。

## 32.4 发布一个可复现版本

发布时固定源码提交、教材版本、测试记录和产物清单。README应提供清楚入口：先读哪一章、怎样运行离线演示、测试如何执行、PDF在哪里、哪些功能未实现。

GitHub可以保存源码与构建流程，Actions产物可用于传递测试或构建结果。[R19] 但临时产物有保留期限，长期阅读版本应采用明确持久位置。教材PDF与源文件应保持一致，构建记录保存实际页数与哈希。

公开仓库不自动意味着任意再使用许可已经确定。许可由项目拥有者选择；本书不替拥有者擅自作出授权决定。引用第三方代码、数据或文献时仍需遵守各自条件。

## 32.5 下一项项目应该小而完整

可以从三个方向选择一个：文献证据核验器、供体层级数据审计器，或微生物—代谢物候选关系报告器。每个项目都有明确输入、输出和验收，比一开始宣布通用自主科学家更容易验证。

例如文献核验器的目标可以是：给定十条claim与指定资料，输出支持、冲突和不足，并给出准确来源位置。它不需要自动分析所有组学，却可以产生直接科研价值。

项目复杂度应随着已验证能力增加，而不是随着架构图中的角色数量增加。每新增一个模块，都应该知道它解决哪种失败。

## 32.6 从工具使用者到方法设计者

完成本书之后，你应能够批评一个Agent架构：它有没有状态？工具有没有契约？证据是否独立？修订是否重新核验？排名有没有被误当成真值？测试是否包含正确拒绝？

进一步的方法创新可以围绕这些问题展开。例如建立证据缺口驱动的资源分配、机制结构感知的去重、来源依赖感知的证据评价，或针对跨组学研究的失败模式基准。创新需要清晰问题和可检验收益，而不只是给模块起新名字。

对自己的算法，先说明假设、输入和优化目标，再设计能够检验优势的任务。不要先把结果画成复杂示意图，最后才寻找评价标准。

## 32.7 给未来自己的研究日志

记录最初的问题、哪些判断被推翻、哪些工具不适用、哪些证据改变了方向。一个月后回看，你应能重建当时的选择，而不是只看到最终故事。

研究Agent最有价值的长期作用，可能不是替你做出所有决定，而是让决定留下清楚的依据，让失败成为可复用知识，让下一位研究者能够继续工作。

本书的终点因此不是一个声称无所不能的程序，而是一套你可以理解、修改、测试和负责的研究系统。

## 32.8 结课练习与参考思路

选择一个真实但合规的小问题，写一页任务契约，准备最小数据与证据，运行一个完整流程，并提交报告、测试和限制。不要要求自己一次解决整个疾病机制。

参考验收包括：输入可追溯、独立单位正确、引用可定位、模拟内容清楚、失败有记录、至少一个错误输入被正确拒绝。完成这些，比生成一份宏大的路线图更接近可靠科研。

**全书核心：**让模型参与决策，让工具完成计算，让证据约束结论，让研究过程能够被检查与纠正。
