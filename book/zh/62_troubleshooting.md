# 附录C 故障排查与修复顺序

## 找不到bioagent模块

先检查是否在正确环境安装项目。终端中的Python、notebook内核与编辑器解释器可能不同。运行 `python -c "import sys; print(sys.executable)"` 查看当前解释器，再用同一个解释器执行可编辑安装。

```bash
python -c "import sys; print(sys.executable)"
python -m pip install -e .
python -c "import bioagent; print(bioagent.__version__)"
```

不要通过把多个未知目录加入系统路径来暂时消除错误。那可能导入另一份旧代码，使测试与实际运行不一致。

## 命令行能运行，Notebook不能运行

通常先检查内核环境，而不是修改业务代码。Notebook应从空内核全部运行；旧变量可能掩盖缺失导入或执行顺序问题。配套notebook通过模块导入复用逻辑，不在单元格中维护多个不同实现。

若使用不同Python环境，需要在对应环境安装ipykernel并选择正确内核。共享Notebook前清除密钥、敏感路径与大体积输出。

## 输出目录已经存在

这是覆盖保护，不是系统坏了。选择新的运行目录可保留旧结果。明确需要替换教学产物时才使用 `--overwrite`。对真实研究，推荐使用运行ID或时间戳组织版本。

不要删除整个研究目录来解决一个输出文件冲突。删除与覆盖是具有副作用的操作，应先确认范围与备份。

## CLR拒绝零值或全零样本

含零意味着需要明确零值处理；全零意味着没有有效组成。先检查数据来源、单位和质量，不要自动加一个常数掩盖问题。固定伪计数需要记录并做敏感性检查。

若出现NaN或无穷值，检查导出、缺失处理和类型转换。数值清洗应依据规则，不是把所有异常替换为0后继续分析。

## Pseudobulk拒绝小数计数

确认输入是否已归一化或log转换。函数要求原始非负整数计数，不应通过四舍五入处理后的表达来通过校验。回到数据说明和层记录，找出真实计数层。

若基因维度不一致，检查细胞向量是否采用相同基因顺序。长度相同仍不保证顺序一致，真实数据应额外保存并核对基因标识。

## 台账始终显示证据不足

先查看是否全部是合成材料、情境是否匹配、方向是否unknown，以及claim标识是否一致。默认排除合成材料是预期行为。真实使用不能通过随意改变标记来获得支持。

若引用存在但仍不足，可能缺少某条关键关系。复合机制需要每条必需claim接受检查，一条强证据不能自动填补其他缺口。

## 检索返回空列表

空查询、语料不覆盖、术语不匹配和接口故障是不同原因。本地检索器会返回合法空结果；联网适配器发生故障时应返回异常，不伪装成没有研究。

可以先用已知存在的词检查索引，再核对实体别名。查询扩展需要记录，避免为了得到结果而改变原问题。

## 模型返回了流畅答案却被拒绝

查看是否满足JSON契约、必填字段与已知claim集合。格式拒绝是为了阻止无法检查的输出进入流程。不要因为文本听起来专业就跳过验证。

必要时可以增加受控格式修复，但保留原始错误，并重新验证引用与字段。格式修复不能添加新的事实或替模型补造来源。

## PubMed网络请求失败

检查网络、联系邮箱、查询长度和服务状态。遵守官方请求限制；多进程与共享IP需要统一限速。认证或参数错误不应无限重试，临时故障也应有最大次数。[R10]

本书的离线测试验证解析样例，不保证当前网络可用。没有成功获得响应时，不输出虚构记录，也不把失败写成“没有文献”。

## 模型API请求失败

检查密钥环境变量、明确模型标识、服务权限与响应状态。不要把密钥复制进聊天、代码或公共问题记录。适配器默认不打印完整请求头，以减少泄露。

远程失败不能转成一个默认的科学答案。预算和网络异常都应保留在状态里，由Supervisor决定停止或人工处理。

## PDF缺字体或无法编译

构建需要Pandoc、XeLaTeX、中文TeX支持和指定字体。缺少字体时安装系统依赖，不把字体文件打包进仓库。编译日志位于 `build/book/`，先检查第一条实质错误，而不是最后的失败摘要。

代码块长行应允许换行，正文代码标识也需要防止越出页边。修改排版后重新编译并检查实际PDF，源文件看起来整齐不等于输出正确。

## 测试通过但真实分析仍失败

测试只能覆盖已设计案例。真实数据可能具有更复杂的缺失、批次和标识问题。保存最小可复现例子，补充测试，再修复相应模块。不要只修改最终报告。

修复顺序通常是输入与权限、程序契约、计算实现、研究方法、证据解释和文字表达。越靠前的问题，越不适合用后面的润色来掩盖。
