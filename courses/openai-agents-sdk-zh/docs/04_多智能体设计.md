# 04 多智能体设计：handoffs 与 agents-as-tools

一个完整的科研项目里，可以有“检索员—方法学审校员—总结撰写员”分工。不过**增加 Agent 并不会自动提高质量**，还会增加 token、延迟和测试复杂度。

## Handoffs（转交）

路由 Agent 识别任务后，把控制权转交给另一个 Agent，由后者负责回答。适合用户问题本身需要由不同专业角色处理的场景，例如生物信息学问题与通用 Python 问题的路由。

## Agents as tools（主控调用子 Agent）

主控始终负责最终回答，在需要时调用 `specialist.as_tool(tool_name=..., tool_description=...)`。适合“同时需要检索与学术表达审校，最后还要按统一格式汇总”的科研流程。

## 什么时候不用多 Agent

如果只有一项工具、一项任务，单个 Agent + 明确指令和验证机制通常更简单、可维护。推荐学习顺序：单 Agent → 工具 → 结构化输出 → 验证 → 子 Agent。
